# Evidence index

Every computational numeric result intended for the report is generated by
`run_analysis.py`. The separate manual verification record is the student's
human-authored confirmation of the generated AP@5 calculation.

- `data_summary.json`: file hashes, join policy, coverage distribution,
  schedule durations, candidate sizes, and data-quality checks.
- `validation_results.csv`: comparable MAP@5, hit rate, recall, warm/cold
  results, and selected parameters for the four reported strategies.
- `tuning_results.csv`: every validation-only parameter trial.
- `association_rule_counts.json`: basket and pair-count diagnostics.
- `business_metrics.csv`: coverage, novelty, repeat rate, and cross-method
  Top-5 overlap.
- `selected_strategy.json`: deterministic selection rule, selected parameters,
  and the predeclared heavy/light user selection rule.
- `selected_users_top5.csv`: side-by-side recommendations with IDs, titles,
  categories, and relevance indicators.
- `selected_users_actual.csv`: validation programs actually watched by the two
  selected users.
- `manual_ap5_check.md` and `.json`: one transparent AP@5 calculation, now
  independently confirmed by the student.
- `manual_ap5_verification.json`: the dated student confirmation, hit ranks,
  manual formula, and agreement with the generated result.
- `submission_checks.json`: row, schema, uniqueness, candidate-pool, and SHA-256
  checks for every prepared submission.
- `kaggle_log.md`: the manually submitted designated-final filename, file hash,
  validation score, returned Kaggle scores, and screenshot provenance.
- `run_manifest.json`: environment, seed, parameters, runtime, peak memory, and
  the explicit test-view leakage guard.

The student manually uploaded `submission_association.csv` and designated it as
the final submission. The other CSV files remain local artifacts and will not
be uploaded. No Kaggle upload is performed by the analysis code.
